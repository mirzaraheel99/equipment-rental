# Glossary

Terms used consistently across ERMS documentation. Where two documents used different words for the same concept, this glossary records the resolution rather than leaving it ambiguous (see Assumptions Register A10).

| Term | Definition |
|---|---|
| **Golden Rule** | The architectural principle that every asset has exactly one authoritative status and one authoritative location at any time, shared identically by every module. Defined in `04-Domain/05-ASSET-REGISTRY-DOMAIN-SPECIFICATION.md` §2. |
| **Asset Registry** | The single source-of-truth domain for asset identity, status, location, meters, certificates, and history. All other domains read asset state from it and write status changes only through its controlled transition service. |
| **Off-hire** | Synonym for **Return** in this repository. The UX screen registry (doc 20) and database dictionary (doc 18) use "off-hire"; the Contract Management domain doc (doc 07) uses "Termination" / "Partial Return" / "Closure." All four terms describe the same real-world event — an asset physically coming back from a customer — from different layers (UX route naming, DB schema naming, contractual-state naming). Resolved as synonyms per Assumptions Register A10. |
| **Contract ceiling** | The maximum committed/authorized value on a contract (often tied to a customer PO ceiling), tracked as original, amended, committed, billed, unbilled, and remaining. Defined in `04-Domain/07-CONTRACT-MANAGEMENT-DOMAIN-SPECIFICATION.md`. |
| **Pricing snapshot** | The frozen, immutable set of rates, discounts, taxes, fees, and terms captured at contract signature. Never recalculated after signature; changes require a formal amendment. |
| **PPM** | Planned Preventative Maintenance — scheduled maintenance triggered by whichever of a time interval or a usage threshold is reached first ("dual-trigger scheduling"). See `04-Domain/13-MAINTENANCE-PPM-DOMAIN-SPECIFICATION.md` §5. |
| **LDW** | Loss Damage Waiver — an optional or mandatory fee (depending on category/customer/project policy) covering damage in lieu of customer-provided insurance. Calculation method owned by Pricing; whether it applies to a given contract line is owned by Contract Management. |
| **COI** | Certificate of Insurance — a customer-provided document establishing insurance coverage, validated by Contract Management before contract finalization. |
| **Master Agreement / Project Agreement / Call-Off Order** | Contract hierarchy for corporate customers: a Master Agreement sets inherited terms, a Project Agreement scopes them to a specific project, and Call-Off Orders are individual transactions drawn against either. Defined in `04-Domain/07-CONTRACT-MANAGEMENT-DOMAIN-SPECIFICATION.md`. |
| **Guarantor Entity (Customer domain)** vs **Guarantor (Contract party role)** | The Customer domain (doc 06 §8.1) lists "Guarantor Entity" as a hierarchy relationship type; the Contract domain (doc 07 §10) lists "Guarantor" as a contract party role. These describe the same real-world party (an entity providing a financial guarantee) from two different structural angles — the customer-hierarchy relationship vs. the contract-signature party role — and are not conflicting concepts, just two facets of one relationship. No renaming performed; documented here to prevent future confusion. |
| **Tenant** | The top-level multi-tenant boundary in ERMS; every business table carries a `tenant_id` and no query may cross it (see Database Dictionary §"tenant_id"). |
| **Legal Entity / Branch / Department** | Organizational hierarchy within a tenant, below the tenant level. A tenant may operate multiple legal entities (e.g. separate CR registrations), each with multiple branches. |
| **Working Draft** | Document status meaning the content reflects current best understanding but has not received final business/stakeholder sign-off. Distinct from "Approved," which no document in this repository currently carries. |
| **Lite (domain doc)** | A domain document explicitly scoped down, per the user-approved hybrid strategy, to cover only what the current MVP vertical slice requires — with a dedicated section listing what was deliberately deferred rather than silently omitted. |
